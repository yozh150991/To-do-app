## ADR-004 — прийнято 2 листопада 2026 року

Локальна база у браузері: та сама Room 3 через `WebWorkerSQLiteDriver` і власний worker на офіційному SQLite WASM з VFS `opfs-sahpool`. Перевірка Ф0 показала, що cross-origin isolation (COOP/COEP) для цього варіанта не потрібна, тож пункт §3.3.1 про хостинг із власними заголовками перестає бути обов'язковим; ціна — одна відкрита вкладка. Власник обрав цей варіант замість кількох вкладок із хостингом, що ставить COOP/COEP. Закриває §14 «Перевірити COOP/COEP і headers фактично обраного worker» і gate Ф0 (c) для Web.

## ADR-003 — прийнято 2 листопада 2026 року

Збірка й доставка APK: основний шлях — `tools/release/build-release.sh` на комп'ютері власника, запасний — workflow Release на GitHub за тим самим тегом; на телефон APK ставиться системним інсталятором (USB `adb install -r` або файл), без застосунку-оновлювача. Перша редакція (1 листопада) пропонувала Obtainium — відхилено власником. Закриває відкрите питання §14 «Obtainium із приватним репозиторієм чи вбудована перевірка» для §3.4 і gate Ф0.

## Незалежний аудит v2.5 (колишній §17 плану) (специфікація vs реалізація)

**Висновок:** три відкриті рішення з v2.4 закриті **як нормативні контракти**: V25-TIME, V25-STACK, V25-RECON. Наявність тексту не засвідчує runtime-сумісність або пройдені тести. Критична межа — Ф0/Ф5b gates із реальними логами; інакше ціль залишається `blocked`, але дані не наражаються на ризик.

| Перевірка | Статус документа v2.5 | Що необхідно довести під час розробки |
| --- | --- | --- |
| Розклад і DST | **Specified**: детермінована політика та golden expectations | Common tests для всіх підтримуваних RRULE, час/zone/versioned parser |
| Перша поява / завершення серії | **Specified**: DTSTART, COUNT, UNTIL, exhausted states | Tests for all day/fixed/floating, skip vs complete, invalid dates |
| Android/JVM/Web компіляція та сховище | **Specified, not verified**: матриця + fallback | Реальні build/runtime reports, pinned versions, перезапуски/міграції |
| Offline Web fallback | **Specified, not verified**: IndexedDB adapter if OPFS fails | Тести транзакцій, outbox, persistence/quota, rebase |
| Stale client / GC | **Specified**: 180/365/365 days, epoch barriers, checkpoints | 400-day offline, interrupted staging, unknown ACK без дублів |
| Продуктовий скоуп Todoist | **Unchanged** from v2.4: exclusions і phased coverage | Реальне dogfooding на Android, import coverage cutover |
| Безпека й backup | **Specified**: RLS, signing, DR, receipts | RPC/security tests, independent backup restore, keystore recovery |

**Невирішених нормативних запитань із трьох пунктів попереднього аудиту немає.** Зафіксовано і окрему небезпеку зайвих full-download після звичайного GC: routine compaction **не піднімає epoch**, а використовує cursor floor (§8.3). Є **неперевірені умови реалізації**, які не можна зняти редагуванням документа. Не вважати будь-яку майбутню фазу готовою без доказів із її DoD. Інші опційні питання §14 лишаються ADR конкретних фаз, а не блокерами старту Ф0.
