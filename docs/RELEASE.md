# Релізи Android APK

Нормативна основа — spec v2.6.1 §3.4. Канал оновлень — [ADR-003](ADR/ADR-003-update-channel.md).

**Головне правило:** нова версія завжди встановлюється **поверх** старої тим самим ключем підпису. Видалити застосунок і поставити заново — означає втратити локальні дані. Без ключа підпису оновити встановлений застосунок неможливо.

## Як це влаштовано

| Що | Де |
| --- | --- |
| Ключ підпису (`todo-release.jks`, PKCS12, RSA 4096, alias `todo-release`) | У власника + дві резервні копії. Ніколи в git |
| Пароль ключа | Менеджер паролів |
| Ключ для CI | Secrets середовища GitHub `release`, лише для тегів `v*.*.*` |
| Відбиток сертифіката (SHA-256) | `.github/release-signing-cert.sha256` у репозиторії |
| Збірка й публікація | `.github/workflows/release.yml` на push тегу `vX.Y.Z` |
| Перевірка конфігурації підпису на кожному PR | `tools/ci/release-smoke.sh` з одноразовим ключем |

Release workflow відмовляється публікувати APK, якщо:
- тег не має вигляду `vX.Y.Z` або вказує на коміт поза `main`;
- тег не новіший за попередній релізний;
- у репозиторії не закріплено відбиток сертифіката;
- APK підписаний іншим сертифікатом, ніж закріплений;
- `versionCode` / `versionName` у зібраному APK не збігаються з тегом.

**Версії.** `versionName` = тег без `v` (`0.1.0`). `versionCode` = `MAJOR × 1 000 000 + MINOR × 1 000 + PATCH`, тож зростає разом із тегами. Debug-збірки мають `applicationId` з суфіксом `.debug` і ставляться поруч із робочою, не замінюючи її.

**ABI.** Release містить лише `arm64-v8a` (ADR-001: менший APK; усі сучасні телефони — arm64). Інший набір: `-PreleaseAbis=arm64-v8a,x86_64`.

## Перше налаштування (один раз, робить власник)

### 1. Створити ключ

На своєму комп'ютері, у порожній папці **поза** репозиторієм (потрібен `keytool` з будь-якого JDK або Android Studio):

```bash
bash /шлях/до/To-do-app/tools/release/create-keystore.sh
```

Скрипт попросить пароль, створить `todo-release.jks` і `todo-release.jks.base64.txt` та надрукує SHA-256 сертифіката.

### 2. Дві незалежні резервні копії

1. **Менеджер паролів:** запис «To-do app release key» з паролем, alias `todo-release`, відбитком SHA-256 і файлом `todo-release.jks` як вкладенням.
2. **Офлайн-носій:** зашифрований USB-накопичувач (наприклад, VeraCrypt-контейнер або зашифрований архів) з тим самим файлом і текстом пароля в окремому місці.

Перевірити копію: `keytool -list -v -keystore <копія>.jks -alias todo-release` має показати той самий SHA-256.

### 3. Закріпити відбиток у репозиторії

PR, який замінює останній рядок `.github/release-signing-cert.sha256` на 64 hex-символи відбитка.

### 4. Secrets у GitHub

Settings → Environments → **New environment** `release`:

- **Deployment branches and tags** → *Selected branches and tags* → додати правило для тегів `v*.*.*`.
- **Environment secrets:**

| Secret | Значення |
| --- | --- |
| `TODO_RELEASE_KEYSTORE_BASE64` | вміст `todo-release.jks.base64.txt` |
| `TODO_RELEASE_KEYSTORE_PASSWORD` | пароль keystore |
| `TODO_RELEASE_KEY_ALIAS` | `todo-release` |
| `TODO_RELEASE_KEY_PASSWORD` | той самий пароль (PKCS12) |

Після цього видалити `todo-release.jks.base64.txt`.

## Випуск версії

1. Оновити `CHANGELOG.md` у PR і злити його в `main`.
2. Поставити тег на коміт у `main` і відправити його:
   ```bash
   git checkout main && git pull
   git tag v0.1.0
   git push origin v0.1.0
   ```
3. Workflow **Release** збере, перевірить і опублікує `todo-v0.1.0.apk` з `.sha256` у GitHub Releases.

Створювати реліз вручну через UI не треба: workflow робить це сам і впаде, якщо реліз із таким тегом уже існує.

**Локальна збірка** (наприклад, для перевірки ключа з резервної копії):

```bash
export TODO_RELEASE_KEYSTORE=/шлях/todo-release.jks
export TODO_RELEASE_KEYSTORE_PASSWORD=… TODO_RELEASE_KEY_ALIAS=todo-release TODO_RELEASE_KEY_PASSWORD=…
./gradlew :androidApp:assembleRelease -PversionName=0.1.0 -PversionCode=1000
```

## Встановлення й оновлення на телефоні

За ADR-003 — через **Obtainium** (якщо ADR прийнято):

1. Встановити Obtainium (F-Droid або його GitHub Releases).
2. «Додати застосунок» → `https://github.com/yozh150991/To-do-app`. Репозиторій публічний, токен не потрібен.
3. Фільтр APK: `todo-v.*\.apk`.
4. Дозволити Obtainium встановлювати застосунки.
5. Оновлення: Obtainium показує нову версію → «Оновити». Встановлення йде поверх, дані зберігаються.

**Ніколи** не видаляти застосунок, щоб «поставити начисто», якщо немає свіжого backup (з Ф1a — експорт у налаштуваннях).

## Відновлення ключа

- **Втрачено комп'ютер або GitHub-secrets:** взяти ключ з будь-якої резервної копії, звірити SHA-256 із закріпленим, заново заповнити secrets.
- **Втрачено ключ повністю (обидві копії):** оновити встановлений застосунок неможливо. Порядок: експорт backup у старому застосунку → новий ключ → PR зі зміною відбитка (окреме рішення власника) → видалити старий застосунок → встановити новий → відновити backup. Тому копій дві й вони незалежні.

## Gate Ф0 для релізів (ручна частина, робить власник)

- [ ] Ключ створено, дві копії перевірено (`keytool -list` з кожної копії дає закріплений SHA-256).
- [ ] Відбиток закріплено в `.github/release-signing-cert.sha256`, secrets середовища `release` заповнено.
- [ ] `v0.0.1` опубліковано workflow і встановлено на телефон через обраний канал; створено тестову задачу.
- [ ] Secrets заповнено **з резервної копії** ключа; `v0.0.2` опубліковано і встановлено поверх `v0.0.1`; тестова задача на місці.

Автоматична частина gate — на кожному PR у CI: release-збірка з одноразовим ключем (`release-smoke.sh`) і оновлення поверх попередньої версії на емуляторі (`upgrade-test.sh`, база PR → поточна гілка, з перевіркою workspace, Inbox, рядків і snapshot міграції).
