## 2. Що входить і що ні

**Входить (spec §11 Ф1a):** CRUD задач і проєктів; підзадачі до 4 рівнів (рішення власника, розділ 8); вкладки «Вхідні · Сьогодні · Майбутні · Огляд» як списки; пріоритети, due date/time, deadline; базовий Quick Add (основні дати й час uk/en/pl, `#проєкт`, `p1`–`p4`); одне авто-нагадування на задачу з часом (exact із fallback, перереєстрація після reboot); мінімальний JSON backup/restore зі збереженням `ExternalIdentity`/`LocalWorkspace`; одноразовий імпорт із Todoist (§9.0) без повторюваних задач і їхніх нащадків; outbox і `TaskActivity` з першого дня (вже є).

**Не входить:** повтори й повний Quick Add (Ф2), кілька нагадувань, snooze-політики й повторювані нагадування (Ф3), віджети (Ф4), хмара (Ф5), мітки й секції в інтерфейсі, пошук, кошик як екран, drag-and-drop (Ф1b), фільтри (Ф6a). Мітки й секції з імпорту зберігаються в базі й backup, але в інтерфейсі Ф1a не показуються.

## 4. Схема v3 (чернетка)

Поля задач для Ф1a вже є з v1 (`priority`, `due_date`, `due_time`, `due_tz`, `deadline`, `parent_id`, `completed_at`, `deleted_at`). Нове в `task`: колонка `duration_days` (ADR-005, ціле ≥ 1, CHECK — не разом із `duration_min`). Нові таблиці:

| Таблиця | Поля (spec §4.2) | Примітки |
| --- | --- | --- |
| `reminder` | `id`, `task_id` (FK), `type` (`absolute`/`relative`/`deadline`/`independent_recurring`), `scope` (`one_shot`/`occurrence_bound`/`task_until_completed`), `occurrence_id?`, `remind_at?`, `offset_min?`, `enabled`, `is_auto`, `repeat_rule?`, `stop_on_task_complete`, `created_at`, `updated_at`, `deleted_at?` | Ф1a використовує лише `relative` + `is_auto` + `one_shot`; решта колонок — щоб Ф3 не мігрував знову. Синхронізується (outbox) |
| `reminder_delivery` | `id`, `reminder_id`, `occurrence_id?`, `device_id`, `planned_at`, `fired_at?`, `snoozed_until?`, `dismissed_at?` | Лише локально, без outbox; стабільний ключ для alarm request code |
| `deferred_todoist_node` | `source_id` (PK), `source_parent_id?`, `source_project_id?`, `source_section_id?`, `root_recurring_source_id`, `depth`, `deferred_reason`, `source_hash`, `import_run_id` | Тільки метадані до Ф2 (FIX-02); жодного `Task` чи вигаданого `parent_id` |

Налаштування (авто-нагадування, зсув) — не в Room, а через спільний інтерфейс `SettingsStore` з адаптерами: DataStore (Android), файл властивостей (Desktop), `localStorage` (Web) — spec §3.

Індекси: `task(due_date)`, `task(deadline)`, `task(completed_at, deleted_at)` для «Сьогодні»/«Майбутніх»; `reminder(task_id)`. Міграція — Room 2 → 3 через `openAppDatabase` зі snapshot (FIX-01): нові таблиці, індекси й колонка `duration_days`. Room не описує CHECK в entity, тож обмеження «не разом із `duration_min`» — або в ручному кроці міграції (`ADD COLUMN … CHECK`, SQLite перевіряє наявні рядки), або в домені й тестах — рішення в PR 2.

## 5. Контракти операцій

Кожна мутація — одна транзакція entity + `task_activity` + `outbox_operation` (уже діє). Payload операцій версіонується (`"v": 1`), бо після Ф5 його читатиме сервер.

| Сутність | Операції Ф1a | `field_patch` |
| --- | --- | --- |
| `task` | `create`, `update`, `complete`, `uncomplete`, `delete`, `restore`, `move` | Лише змінені поля: `content`, `description`, `priority`, `due_date`, `due_time`, `due_tz`, `deadline`, `duration_min`, `duration_days`, `project_id`, `parent_id`, `child_order`. Перенесення чи видалення піддерева — окрема операція на кожну змінену задачу, усі в одній транзакції й одній групі Undo |
| `project` | `create`, `update`, `archive`, `unarchive`, `delete` | `name`, `color`, `parent_id`, `child_order`, `is_favorite`; `delete` несе вибір долі задач (перемістити в Inbox / видалити разом) |
| `reminder` | `create`, `update`, `delete` | Повний запис при `create`, змінені поля при `update` |
| імпорт / restore | без outbox на кожен рядок | Restore у порожнє сховище переносить outbox і `local_seq` з backup як є (§3.2: не генерувати тисячі дублів); `ExternalIdentity` зберігає `local_id` |

Undo — нова операція (наприклад, `uncomplete` після `complete`), а не видалення запису з outbox.

## 6. Ризики

| Ризик | Що робимо |
| --- | --- |
| Android 14+ не дає `SCHEDULE_EXACT_ALARM` за замовчуванням застосункам поза Play | Inexact fallback з поясненням і кнопкою дозволу (UX_SPEC §10); у тестовому звіті розділяти точну й fallback-доставку |
| Обмеження батареї Samsung/інших | Підказка лише в контексті, ручна перевірка на телефоні власника (§7.3) |
| Неоднозначні дати в Quick Add (відмінки, `03.04`) | Golden-таблиця трьома мовами, прев'ю з вибором, повернення в назву; парсер ніколи мовчки не змінює текст |
| Три мови одночасно дають хибні збіги (слово з однієї мови як дата в іншій) | Окремий набір golden-фраз «звичайний текст, не дата» для кожної мови; чипи-прев'ю й повернення фрази в назву одним тапом |
| Підзадачі й «Майбутні» як у Todoist розширюють Ф1a | Підзадачі — окремий PR 4 після списків, перетягування лишається у Ф1b; «Майбутні» — лінивий список днів із запитом задач лише для видимого діапазону |
| Формат backup стає довгостроковим контрактом | Версія формату з першого дня, golden-файл у тестах, відмова від новішої версії |
| Зміни Todoist API v1 і ліміти | Модуль маппінгу окремо, фікстури в CI, dry-run перед записом; токен лише в змінній оточення |
| Міграція схеми на телефоні з реальними даними | FIX-01 snapshot/відкат, upgrade-тест у CI з попередньої версії, backup перед кожним оновленням (UX нагадує) |
| Розростання обсягу | Лише пункти розділу 2; усе інше — у відповідну фазу |

## 7. Приймання Ф1a (spec §11)

- [ ] Тиждень щоденного використання на основному телефоні без втрати задач.
- [ ] Реальні задачі з Todoist імпортовані; `ExternalIdentity` задач/проєктів/секцій/міток стабільні після backup → restore; повторювані корені разом із транзитивними нащадками не імпортовані й обліковані у звіті.
- [ ] Неповторювані задачі, що не є нащадками відкладених коренів, імпортовано повністю; кількість відкладених коренів і нащадків збігається з Todoist; жодного orphan `parent_id`.
- [ ] Нагадування для задачі з часом приходить і після перезавантаження телефона.
- [ ] Export → restore у чисте сховище повертає дані без пошкоджень.
- [ ] Невдале локальне збереження не залишає сутність без outbox або навпаки.
