# ADR-003: Збірка й доставка Android APK на телефон

- **Статус:** Accepted
- **Дата:** 2 листопада 2026 року (перша редакція 1 листопада пропонувала Obtainium; власник відхилив сторонній застосунок)
- **Власник рішення:** власник проєкту
- **Стосується v2.6.1:** §3.4 «Канал оновлень», Ф0 (пункт «канал оновлень APK (ADR)» і gate «оновлення v0.0.1 → v0.0.2 обраним каналом»), §14 «Потрібно перевірити: Obtainium із приватним репозиторієм чи вбудована перевірка»

## Контекст

- Застосунок поширюється як підписаний APK без Google Play (§1, §3.4). Специфікація передбачала публікацію в GitHub Releases і залишила відкритим вибір між Obtainium і вбудованою перевіркою оновлень.
- Оновлення має ставитись поверх тим самим ключем; видалення застосунку знищує локальні дані (інваріант §2.1.9).
- Власник не хоче сторонніх застосунків на телефоні й хоче збирати APK на своєму комп'ютері. Водночас workflow збірки на GitHub уже налаштований (secrets середовища `release`).

## Рішення

1. **Без застосунку-оновлювача.** Ні Obtainium, ні вбудованої перевірки оновлень у Ф0–Ф4. APK встановлюється системним інсталятором Android.
2. **Основний шлях — збірка на комп'ютері власника** скриптом `tools/release/build-release.sh`: збирає лише чистий `origin/main`, перевіряє монотонність версії, звіряє ключ із `.github/release-signing-cert.sha256` до збірки, а підпис, версію й ABI — у готовому APK; результат — `dist/todo-vX.Y.Z.apk` + `.sha256`; створює тег `vX.Y.Z`.
3. **Запасний шлях — збірка на GitHub** тим самим тегом (`.github/workflows/release.yml`, ключ у secrets середовища `release`), APK на сторінці Releases. Той самий код, ключ і перевірки, тож обидві копії однієї версії ставляться одна поверх одної.
4. **Доставка на телефон:** кабель USB (`adb install -r`, пропонує скрипт) або файл через месенджер / хмару / кабель, або завантаження зі сторінки Releases у браузері телефона. Завжди поверх наявної версії.

## Наслідки

- Ключ у роботі в двох місцях: комп'ютер власника і GitHub secrets (плюс дві офлайн-копії). Прийнято заради запасного шляху; якщо він стане не потрібен — видалити середовище `release` із secrets, основний шлях від нього не залежить.
- Для основного шляху на комп'ютері потрібні Android Studio (JDK і Android SDK) і Git for Windows. Перша збірка — 10–15 хвилин.
- Повідомлень про нові версії на телефоні немає: власник сам ставить новий APK після збірки.
- Дозвіл «встановлювати невідомі застосунки» Android видає тому застосунку, з якого відкрито APK (Telegram, Файли, Chrome); окремий застосунок для цього не потрібен.
- CI на кожному PR проганяє `create-keystore.sh` і `build-release.sh` наскрізно з одноразовим ключем на Linux і Windows (Git Bash), тож скрипти власника не зламаються непомітно.

## Перевірка

- [ ] `v0.0.1` зібрано `build-release.sh` на комп'ютері власника і встановлено на телефон.
- [ ] `v0.0.2` зібрано з ключем, відновленим із резервної копії, і встановлено поверх без втрати тестової задачі.
- [ ] Запасна копія `v0.0.1` або `v0.0.2` з'явилась у GitHub Releases після push тегу.

## Розглянуті альтернативи

- **Obtainium** (перша редакція цього ADR): автоматичні повідомлення й оновлення з GitHub Releases. Відхилено власником: сторонній застосунок на телефоні.
- **Вбудована перевірка оновлень у застосунку:** потребує коду, дозволу на встановлення пакетів і мережевого запиту; не виправдана для одного користувача на цьому етапі.
- **Лише GitHub-збірка:** не потребує Android Studio на комп'ютері, але власник хоче збирати локально; залишена як запасна.
