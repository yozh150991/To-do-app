# ADR-003: Канал оновлень Android APK

- **Статус:** Proposed (чекає рішення власника)
- **Дата:** 1 листопада 2026 року
- **Власник рішення:** власник проєкту
- **Стосується v2.6.1:** §3.4 «Канал оновлень», Ф0 (пункт «канал оновлень APK (ADR)» і gate «оновлення v0.0.1 → v0.0.2 обраним каналом»), §14 «Потрібно перевірити: Obtainium із приватним репозиторієм чи вбудована перевірка»

## Контекст

- Застосунок поширюється як підписаний APK через GitHub Releases, без Google Play (§1, §3.4).
- Оновлення має ставитись поверх тим самим ключем; видалення застосунку знищує локальні дані (інваріант §2.1.9).
- Специфікація залишила відкритим вибір між Obtainium і вбудованою перевіркою нової версії. Питання про токен для приватного репозиторію знято: репозиторій `yozh150991/To-do-app` зараз **публічний**, тож GitHub Releases доступні без автентифікації.

## Варіанти

| | Obtainium | Вбудована перевірка в застосунку |
| --- | --- | --- |
| Код у застосунку | Немає | Запит до GitHub API, порівняння `versionCode`, екран «доступна нова версія», завантаження APK |
| Дозволи застосунку | Не змінюються | `INTERNET` уже потрібен для синхронізації (Ф5); для встановлення ще `REQUEST_INSTALL_PACKAGES` або перехід у браузер |
| Сповіщення про нову версію | Фонові перевірки Obtainium | Треба писати самим (WorkManager) |
| Перевірка підпису перед встановленням | Android перевіряє збіг ключа при оновленні; Obtainium показує помилку | Те саме + власна логіка |
| Залежність від стороннього застосунку | Так (open source, F-Droid) | Ні |
| Якщо репозиторій стане приватним | Потрібен read-only токен у налаштуваннях Obtainium | Токен у застосунку — заборонено (§8.4), тож лише публічний endpoint або власний сервер |
| Обсяг роботи у Ф0 | Інструкція (`docs/RELEASE.md`) | Окремий модуль, UI, тести |

## Рішення (пропозиція)

1. **Основний канал — Obtainium**, що відстежує GitHub Releases репозиторію, фільтр APK `todo-v.*\.apk`.
2. Вбудовану перевірку не робимо у Ф0–Ф4. Повернутися до питання, якщо Obtainium перестане влаштовувати або репозиторій стане приватним; тоді — окремий ADR.
3. Release workflow публікує поруч з APK файл `.sha256`, щоб завантаження можна було звірити вручну.

## Наслідки

- Для gate Ф0 «оновлення v0.0.1 → v0.0.2 обраним каналом» власник встановлює обидві версії через Obtainium (чекліст у `docs/RELEASE.md`).
- Якщо репозиторій стане приватним, Obtainium потребуватиме personal access token з правом лише читання релізів; його не можна передавати в застосунок або CI-логи.
- Публічні релізи означають, що APK може завантажити будь-хто. Секретів у ньому немає (ключі Supabase з'являться лише як publishable key з RLS, §8.4), тож прийнятно.

## Перевірка

- [ ] Власник додав репозиторій в Obtainium і отримав `v0.0.1`.
- [ ] Obtainium запропонував `v0.0.2` і встановив її поверх без втрати тестової задачі.
